# Pull Requests

Ein Pull Request (PR) ist eine Anfrage, einen Branch in einen anderen zu mergen. Er findet auf Plattformen wie GitHub oder GitLab statt, nicht in Git selbst.

**Ablauf:** Man entwickelt in einem eigenen Branch, öffnet einen PR, wählt Quell- und Zielbranch und beschreibt die Änderungen. Andere Teammitglieder kommentieren den Code, schlagen Änderungen vor oder geben ihn frei. Sind alle zufrieden, wird der PR gemergt.

**Merge-Optionen:** normaler Merge mit Merge-Commit, Squash-Merge (alle Commits zu einem zusammengefasst) oder Rebase-Merge (lineare Geschichte ohne Merge-Commit).

**Draft PR:** Ein PR lässt sich als Entwurf öffnen, solange die Arbeit noch läuft. Das signalisiert dem Team, dass noch kein Review erwartet wird.

Pull Requests erzwingen eine bewusste Entscheidung bevor Code in den Hauptbranch gelangt – Fehler werden früher entdeckt, Wissen wird geteilt.
